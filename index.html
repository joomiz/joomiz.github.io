How it works

Three commands, in this order

The same three steps for every change, from the first deployment to a new database.

  1. joomiz validate Checks the file against your platform team's rules and reports every problem. It changes nothing. Checks the file. Changes nothing. joomiz.yaml is valid
  2. joomiz plan Shows what would change in one environment, and what drifted. It changes no infrastructure. Shows what would change. Changes nothing. plan succeeded. Nothing was changed.
  3. joomiz apply Makes the change. It refuses a file that was not planned for that environment. Makes the change, only from a plan. apply succeeded

No account, no installation

Questions we hear

Read the FAQ

Isn't this just Terraform?

Joomiz borrowed the plan and apply steps from Terraform on purpose. Terraform is a tool for describing infrastructure in code.

Read the answer

How is this different from a developer portal like Backstage?

Backstage is an open-source framework for building a developer portal. Joomiz is not a portal.

Read the answer

Does Joomiz see our passwords?

A joomiz.yaml file never holds a secret. A provisioner stores a secret, such as a database password, in a vault.
