Describe the service. Joomiz provides it.

Joomiz is a Golden Path for Java and Kotlin Spring Boot services. Developers describe what an application needs in one file. The platform team decides how it is provided. Every change is shown before it runs.

Joomiz is early and has no production deployments yet, so we start with a conversation.

Three commands, in this order

  1. joomiz validate checks the file against your platform's rules and reports every problem. It changes nothing.
  2. joomiz plan shows what would change. It changes nothing.
  3. joomiz apply makes the change.

What changes for each team

Developers

  • One file in your repository, next to your code.
  • Check it before you push. Preview every change before you apply it.
  • Completion and checks in VS Code.

Platform teams

  • Define the rules and the building blocks once.
  • Add a building block with a catalog entry and a provisioner. A provisioner can use Terraform or any other tool.
  • Every change goes through the same rules.

Architects

  • The file states the result. The control plane owns the state.
  • Provisioners follow a published OpenAPI contract, so you can add your own.
  • Each building block has a closed, validated schema. Mistakes are rejected before anything runs.

Engineering managers

  • A new service starts from one standard path.
  • Sensitive outputs are recorded in an audit trail.
  • A team can act only on its own applications. Secret values never reach the control plane.
