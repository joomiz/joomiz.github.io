Get a database without a ticket

Add a postgres entry to your joomiz.yaml. Joomiz asks the provisioner your platform team registered to create the database. Your application gets the password as a reference, not as text.

Email us Read the docs

Without Joomiz

A team opens a ticket and waits. Someone creates the database manually and sends the password in chat or in a file. Nobody records the request, and the next environment starts from zero again.

With Joomiz

  1. Declare the database

    Add a managed resource of type postgres to an environment. The schema of the type lists the settings you may write: flavor, version, storage-gb and multi-az.

  2. Reference the password

    In the env setting of your deployment, write a reference to the password output of the database. The file never holds the password.

  3. Preview the change

    joomiz plan changes nothing. It lists the database first. The password shows as (known after apply), because the database does not exist yet.

  4. Apply the change

    joomiz apply asks the provisioner to create the database. Your application receives the address of the secret, not the secret itself.

What you get

  • A database from one reviewed change to a file, not from a ticket queue.
  • A password that never appears in the file, the plan or the apply output.
  • The same request for the next environment, written in the same file.

The rules that still hold

  • The catalog schema sets the allowed settings. For example, storage-gb must be from 1 to 65536.
  • You act only for your own team. Other teams' applications are refused.
  • Only one apply runs at a time for each application and environment.
