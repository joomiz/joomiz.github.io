Publish an API through Kong, with its consumers

Describe your API with an OpenAPI document. Add a Kong target and a kong-api deployment. List the consumers and their roles in the same file, and review the change in a plan.

Email us Read the docs

Without Joomiz

Publishing an API means a request to the gateway team. Consumers are added through another request, often by message. The OpenAPI document, the gateway setup and the consumer list live in three places and do not match.

With Joomiz

  1. Declare the OpenAPI document

    Add an artifact of type kong-oas. Its path names the OpenAPI document in your repository. Joomiz does not check that the file exists.

  2. Name the Kong control plane

    Add a target of type kong-gateway. It names the Kong control plane that your environment publishes APIs onto.

  3. Publish with consumers

    Add a kong-api deployment. It puts the artifact on the target. Each consumer has an id, a name and optional roles on the API.

  4. Review a consumer change

    Add or remove a consumer, then run joomiz plan. Only the Kong deployment changes. The jar and the database are not in the plan.

What you get

  • The API, its gateway and its consumers described in one reviewed file.
  • A consumer added or removed by a one-line change and a plan.
  • A plan that lists only what changed, so reviewers read less.

The rules that still hold

  • A kong-api deployment accepts only a kong-oas artifact and a kong-gateway target.
  • One deployment lists at most 100 consumers.
  • The platform team decides which Kong control plane names and provisioners exist.
