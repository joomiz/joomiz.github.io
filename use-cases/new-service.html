Start a new service on the golden path

Describe a new service in one file, joomiz.yaml. Name a golden path that your platform team offers. Then register, check, preview and apply the change with the Joomiz CLI (command line interface).

Email us Try it in the simulator Read the docs

Without Joomiz

A new service starts by copying an old one. Pipeline files, settings and names drift apart. Nobody can say which services follow the supported way to build, and each team repeats the same setup work.

With Joomiz

  1. Create the file

    joomiz init writes a joomiz.yaml with the application block. The golden-path value is one of the names your platform team offers. The command does not contact the control plane.

  2. Register the application

    Registration stores the identity of the application, its owner, and the artifacts and tooling lists. You do it once.

  3. Check and preview

    joomiz validate checks the whole file. joomiz plan lists what apply would create, and changes nothing. Your editor shows the same checks while you type.

  4. Apply the change

    Run joomiz apply with the same file. Joomiz saves every plan and every apply as a run, and joomiz runs lists them.

What you get

  • A registered application with an owner, a golden path and a first environment.
  • A plan that shows every change before anything is applied.
  • Checks in your editor and in joomiz validate before the first apply.

The rules that still hold

  • The platform team decides which golden paths and types exist.
  • You act only for your own team. Other teams' applications are refused.
  • joomiz apply refuses a file you did not plan. Plan again with the changed file.
