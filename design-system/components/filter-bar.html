Filter bar

A form of selects and inputs above a list, with an Apply button and a Reset button. The fields sit side by side while there is room. The form has no action: a script reads the controls and builds the query that the list needs. The form has a name for a screen reader, so it is a landmark.

Inputs

Inputs of the filter bar component
Input Type Required Default Description
label string Yes None The name of the form for a screen reader, such as "Filter the runs".
fields list of objects Yes None The fields, in order. Each is a form-field component.
apply string No Apply The text of the button that applies the filters.
reset string No Reset The text of the button that clears them.
Fields of "fields"
Field Type Required Description
id string Yes The id of the control. It is unique on the page.
label string Yes The visible name of the field.
name string No The name of the control, which a script can use as the name of a query parameter. Without it the id is the name.
type string No The kind of control. Without it the field is a text input.
One of: "text", "url", "email", "number", "search", "date", "datetime-local", "select"
value string No The value that the control starts with, and that Reset goes back to.
hint string No A help text under the control.
options list of objects No The options of a select. Each has value, label and, for the chosen one, selected. Add an option with an empty value to mean "any".

Source

The template is src/components/filter-bar.html.

{% comment %}
  A form of filters for a list: form fields, then Apply and Reset.
  The inputs, with a description and examples, are in filter-bar.json. The components pages show them.

  Each field is a form-field, so it has a label, a hint and an error like any other field. The form has no action. A script
  reads the controls on submit, builds the query of the address from their names, and loads the list again. Reset puts every
  control back to the value that it has in the markup, so a script that keeps the filters in the address clears them too.

  A field takes the place of a property of the form that has its name: with a field named "action" (the audit filter has one),
  `form.action` is that field and not an address. So a script reads the controls with `new FormData(form)`, and never through a
  property of the form such as `form.action`, `form.method` or `form.submit`.
{% endcomment %}
<form data-variant="filter" aria-label="{{ label }}">
  {%- for field in fields %}
  {%- assign field_type = field.type | default: "text" %}
  {%- assign field_name = field.name | default: field.id %}
  {%- assign field_value = field.value | default: false %}
  {%- assign field_options = field.options | default: false %}
  {%- assign field_hint = field.hint | default: false %}
  {% render "form-field.html", id: field.id, label: field.label, name: field_name, type: field_type, value: field_value, options: field_options, hint: field_hint, required: false, error: false, rows: false, maxlength: false, autocomplete: false %}
  {%- endfor %}
  <div data-slot="actions">
    <button type="submit" data-variant="primary">{{ apply | default: "Apply" }}</button>
    <button type="reset">{{ reset | default: "Reset" }}</button>
  </div>
</form>
