Components

The building blocks that the page layouts are built from. Each has a page that shows it rendered, with its usage, its source and its inputs.

The components of the design system
Component What it is Inputs
Brand The Joomiz wordmark as a link home, with optional text beside it. Both colour versions of the logo are in the page, and the CSS shows the one that fits the theme. label, href
Cell The content of one table cell: plain text, code, bold text, a link, a date or a status badge, with an optional line of small text under it. The data table uses it for every cell. cell
Code block Lines of code or command output, in a preformatted block. Every line is escaped, so text such as <b> shows as text. lines
Confirm dialog A native <dialog> that asks the reader to confirm an action that cannot be undone. It has a title, a text that says the effect, an optional field where the reader types a name, a danger button and a Cancel button. Focus starts on Cancel. A script opens it with showModal(), enables the danger button when the typed text equals the name, and returns focus to the control that opened it (a native dialog does this on close). id, title, effect, action, cancel, confirm_name, open, children
Data table A table that scrolls sideways on a small screen, and that a keyboard user can scroll too. The first column stays in view while the rest scrolls. id, caption, columns, rows, row_header
Error summary A box at the top of a form that lists the problems, each as a link to the field that has it. It is hidden while there is no problem. After a failed submit a script fills it, shows it and moves focus to it, so a keyboard and a screen reader user hear the problems first. It has role="alert". id, title, errors
Facts Facts about one thing, as a description list: a label and a value for each fact. items
Filter bar A form of selects and inputs above a list, with an Apply button and a Reset button. The fields sit side by side while there is room. The form has no action: a script reads the controls and builds the query that the list needs. The form has a name for a screen reader, so it is a landmark. label, fields, apply, reset
Form field A label, a control, a hint and an error message, linked with for, aria-describedby and aria-invalid. The control is a native input, select or textarea. The error message is always in the markup and stays hidden until it has text, so a script that checks the form only sets the text and aria-invalid. id, label, name, type, value, hint, error, required, maxlength, autocomplete, rows, options
List pager The controls under a list that a script loads. Mode "more" is for a list that has a cursor: a "Load more" button and a text such as "Showing 100". Mode "pages" is for a numbered list: Previous and Next buttons and a text such as "Page 2 of 7". The text is a status region. A button that is disabled cannot keep focus, so a script that disables the button with focus moves focus to the list or to the other button. mode, summary, label, more_label, done, previous_label, next_label, first, last
Live table A table that a script fills. It looks and scrolls like the data table, but its body is empty and one row is in a template. The script clones the template for each record, so the markup of a cell comes from the build and only text comes from the script. id, caption, columns, row, row_header
Menu The groups of a left menu: a heading and a list of links for each group. The link of the current page is marked. groups, current
Nav A list of links in a navigation landmark, such as the main navigation in a header. The link of the current page is marked. An item can have children, which show in a list under it when the pointer is over it or focus is in it. label, items, current, base
Note A short message that stands out from the text around it, in one of four tones. It takes a body, which you write between the component tags. variant, role, children
Page head The title of a page, with a one-line lead under it. title, lead, id
Pager The links to the previous page and the next page, at the end of a page that belongs to a series, such as a guide. Each link shows the title of its page. The first page has only Next, and the last page has only Previous. previous, next, label
State panel What a block of a screen shows when it has no data: an empty list, a wait, or a failure. It has a title, an optional text and an optional action, such as "Try again". The loading state sets aria-busy="true" and is a status region. The error state is an alert. The title says which state it is, so colour is never the only signal. state, title, text, action_label, action_href
Status badge A short text label with a tone: neutral, info, success, warning or danger. The label is always text, so colour is never the only signal. A script changes the tone by setting data-tone, and the text by setting textContent. label, tone
Theme toggle An icon button at the end of a header. It goes round the system setting, light and dark. The icon shows the choice, and the label says what a click does. The choice is kept, so every page of the site follows it. None

Add a component

Write the template in src/components/, and write its spec next to it with the same name and the extension .json. The build checks the spec against the template, renders the examples with the real component, and adds the page and the menu entry. The README says what a spec holds.
