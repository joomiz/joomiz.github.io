Error summary

A box at the top of a form that lists the problems, each as a link to the field that has it. It is hidden while there is no problem. After a failed submit a script fills it, shows it and moves focus to it, so a keyboard and a screen reader user hear the problems first. It has role="alert".

Examples

Two problems

Rendered

There is a problem

  • Name: enter a name of 1 to 255 characters.
  • Types: add at least one type.

Usage

{% render "error-summary.html", id: "problems", errors: errors %}

The data that the usage names

{
  "errors": [
    { "field": "name", "text": "Name: enter a name of 1 to 255 characters." },
    { "field": "types", "text": "Types: add at least one type." }
  ]
}
The HTML that the component writes 
<div id="problems" data-variant="error-summary" role="alert" tabindex="-1" aria-labelledby="problems-title">
  <h2 id="problems-title">There is a problem</h2>
  <ul>
    <li><a href="#name" data-field="name">Name: enter a name of 1 to 255 characters.</a></li>
    <li><a href="#types" data-field="types">Types: add at least one type.</a></li>
  </ul>
</div>

Inputs

Inputs of the error summary component
Input Type Required Default Description
id string Yes None An id that is unique on the page. The id of the title comes from it, and the box is named by the title.
title string No There is a problem The title of the box. It is a level 2 heading.
errors list of objects No None The problems, in the order of the fields. Leave it out, or give an empty list, for a box that starts hidden.
Fields of "errors"
Field Type Required Description
field string Yes The id of the control that has the problem. The link goes to it.
text string Yes What is wrong and how to fix it. It is the text of the link, so it names the field.

Source

The template is src/components/error-summary.html.

{% comment %}
  The list of the problems of a form, as links to the fields that have them.
  The inputs, with a description and examples, are in error-summary.json. The components pages show them.

  It is hidden while it has no problem. A script that finds problems fills the list, shows it, and moves focus to it.
  tabindex="-1" lets a script focus it. The links keep their `href="#<id>"`, so they work without a script, and `data-field`
  names the field for a script that uses the hash for something else.
{% endcomment %}
<div id="{{ id }}" data-variant="error-summary" role="alert" tabindex="-1" aria-labelledby="{{ id }}-title"{% unless errors.size > 0 %} hidden{% endunless %}>
  <h2 id="{{ id }}-title">{{ title | default: "There is a problem" }}</h2>
  <ul>
    {%- if errors %}
    {%- for error in errors %}
    <li><a href="#{{ error.field }}" data-field="{{ error.field }}">{{ error.text }}</a></li>
    {%- endfor %}
    {%- endif %}
  </ul>
</div>
