Confirm dialog

A native <dialog> that asks the reader to confirm an action that cannot be undone. It has a title, a text that says the effect, an optional field where the reader types a name, a danger button and a Cancel button. Focus starts on Cancel. A script opens it with showModal(), enables the danger button when the typed text equals the name, and returns focus to the control that opened it (a native dialog does this on close).

Examples

With a name to type

Rendered

Deregister kafka?

This removes the registration now. Plan and apply for these types fail until another provisioner claims them.

  • managed-resource/kafka-topic
  • managed-resource/kafka-acl

Usage

{% component "confirm-dialog.html",
     id: "deregister",
     title: "Deregister kafka?",
     effect: "This removes the registration now. Plan and apply for these types fail until another provisioner claims them.",
     action: "Deregister",
     confirm_name: "kafka",
     open: true %}
  <ul><li><code>managed-resource/kafka-topic</code></li><li><code>managed-resource/kafka-acl</code></li></ul>
{% endcomponent %}
The HTML that the component writes 
<dialog id="deregister" data-variant="confirm" aria-labelledby="deregister-title" aria-describedby="deregister-effect" open>
  <h2 id="deregister-title">Deregister kafka?</h2>
  <p id="deregister-effect">This removes the registration now. Plan and apply for these types fail until another provisioner claims them.</p>
  <ul><li><code>managed-resource/kafka-topic</code></li><li><code>managed-resource/kafka-acl</code></li></ul>
  <div data-variant="field">
    <label for="deregister-confirm">Type <code data-slot="confirm-name">kafka</code> to confirm</label>
    <input id="deregister-confirm" type="text" autocomplete="off" autocapitalize="off" spellcheck="false">
  </div>
  <form method="dialog">
    <button type="submit" value="cancel" autofocus>Cancel</button>
    <button type="submit" value="confirm" data-variant="danger" data-action="confirm" disabled>Deregister</button>
  </form>
</dialog>

Inputs

Inputs of the confirm dialog component
Input Type Required Default Description
id string Yes None An id that is unique on the page. The ids of the title, the effect text and the field come from it.
title string Yes None The question, such as "Deregister kafka?". It names the thing, because the dialog is named by it.
effect string Yes None What happens when the reader confirms, in one or two sentences. It is the description of the dialog.
action string Yes None The text of the danger button. Use a verb, such as "Deregister".
cancel string No Cancel The text of the button that closes the dialog with no change.
confirm_name string No None A name that the reader must type. The dialog then shows a field, and the danger button is disabled until a script finds the same text in it. Leave it out for a dialog with no field.
open boolean No None Writes the dialog open. It is for a demonstration, such as this page. A script that calls showModal() on a dialog that is already open fails, so do not use it in a screen.
children html No None More content between the effect text and the field, such as the list of what the action touches. Write it between the component and endcomponent tags. It is trusted markup, so escape any text that a reader typed.

{% comment %}
  A native dialog that asks for confirmation before an action that cannot be undone.
  The inputs, with a description and examples, are in confirm-dialog.json. The components pages show them.

  A script opens it with dialog.showModal(), which traps focus and closes on Escape. Focus starts on Cancel (autofocus),
  so Enter or Space on a dialog that has just opened cannot confirm. The field for the name is outside the form on purpose:
  Enter in a field of a form with method="dialog" would submit it, and a mistyped Enter must not confirm.
  A script that waits for the server calls preventDefault() on the click of the action button, and closes the dialog itself.
{% endcomment %}

  {%- endif %}
